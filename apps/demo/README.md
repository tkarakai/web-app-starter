# Northstar Dispatch demo

A standalone demonstration of a responsive dashboard: resizable/collapsible
sidebar, mobile navigation, custom branding and an interactive freight dispatch
board. There is no backend or authentication to configure.

```bash
bun install --frozen-lockfile          # repository root
bun run --cwd apps/demo dev
bun run --cwd apps/demo test:unit
bun run --cwd apps/demo build
```

The demo is also a realistic customized application used to test starter
upgrades. That rehearsal runs on a copy; it does not replace the demo or reset
its business rules, navigation, styling or icon.

## Where to make changes

| Location | Owner | Can the starter upgrader replace it? |
|---|---|---|
| `src/`, including `components/ui/` | Application; edit freely | No |
| `public/northstar.svg` | Application branding | No |
| `qa/`, configuration and this README | Application | No |
| `starter-packages/sidebar-policy/` | Consumed `@web-app-starter/starter-sidebar-policy` release | Only from an exact known version through an approved plan; do not hand-edit |
| `.next/`, `node_modules/`, TypeScript build info | Generated by build/package tools | Rebuilt, not application source |
| `starter-upgrade.lock.json`, `.starter-upgrade/` | Generated upgrade identity and evidence | Written by the upgrade tool |

`starter-upgrade.json` records these boundaries. There is no supported vendored
starter category yet: the copied/shadcn-style UI is application-owned, not
simultaneously editable and package-managed.

## Test a starter upgrade

```bash
bun run check:starter-ownership
bun run test:starter-upgrade
bun run test:starter-rehearsal
```

The checked-in dependency is package `1.0.1`. The rehearsal installs immutable
`1.0.0` in a copy, reproduces the sidebar's non-finite-width bug, upgrades to
`1.0.1`, and runs regression/business tests, typecheck and a production build.
Every application-owned file must stay unchanged. Fixtures live in
`qa/fixtures/starter-releases/`; generated reports live outside the demo source
in `.ci-local-artifacts/starter-upgrade/` at the repository root.

The package is consumed through its exports and local `file:` dependency, never
through the author workspace source. When replacing a local package manually,
refresh Bun's cache with `bun install --force --frozen-lockfile`; normal installs
use the checked-in version. Upgrade verification checks the installed bytes too.

[`UPGRADING.md`](../../UPGRADING.md) explains the complete procedure. Releases are prepared by starter authors, upgrades are
reviewed application PRs, and operations deploys the resulting approved commit.
None of the upgrade commands deploys or changes the operations tooling.

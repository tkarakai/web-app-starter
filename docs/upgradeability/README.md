# Upgradeability working drafts

Working drafts on how downstream business apps keep taking starter fixes, improvements and new features. These are exploration notes, not adopted plans.

| File | What it is |
| --- | --- |
| [handoff.md](handoff.md) | The original design brief: a mix of developed and undeveloped ideas |
| [brainstorm-v1.md](brainstorm-v1.md) | First brainstorm: the brief argued topic by topic, from the code alone |
| [case-study-lifeor2-client.md](case-study-lifeor2-client.md) | First real app built on the starter, with a trial upgrade merge |
| [brainstorm-v2.md](brainstorm-v2.md) | Current brainstorm, revised with the case study; includes the evidence log for future apps |
| [repo-separation-v1.md](repo-separation-v1.md) | First draft: which files belong to the starter, the app and the maintainer |
| [repo-separation-v2.md](repo-separation-v2.md) | Second draft: `platform/` zone, private maintainer repo, adopt and upgrade flow, Convex component, release process |
| [repo-separation-v3.md](repo-separation-v3.md) | Third draft: the three-layer instruction model, gaps and fixes, CI as a selling point |
| [repo-separation-v4.md](repo-separation-v4.md) | Current draft: adds Agent Skills, verified instruction loading, update delivery via a shipped workflow, verified CI plan limits |

Earlier upgrade work lives in `docs/starter-upgrades.md` and `docs/starter-versioning-strategy.md`; these drafts were written independently of it.
